# English Coach — руководство по проекту

Этот файл описывает проект для разработчиков и помощников по коду. Название
сохранено для совместимости с инструментами; использование Claude не требуется.

## Текущее состояние

- Сайт: React + TypeScript + Vite. API: FastAPI, SQLAlchemy 2, PostgreSQL 16.
- Telegram: aiogram 3, подключённый режим по умолчанию; только обращения к API.
- Курс: 15 тем A1–B1, 90 упражнений четырёх типов, теория и слова уроков.
- Словарь: 6 тематических модулей, 36 карточек с локальными SVG-иллюстрациями.
- Диагностика: 24 вопроса, серверная проверка, история и разбор; отдельная кнопка применения уровня.
- Личный кабинет: общая статистика, прогресс курса, история тестов, настройки напоминаний.
- Напоминания: opt-in, время и IANA timezone, история доставки в PostgreSQL.
- **LLM сейчас не подключена.** Рабочая локальная настройка — `LLM_PROVIDER=stub`.
  ИИ-собеседник и составление плана с ней недоступны. Anthropic — прежняя интеграция;
  не включать и не настраивать провайдеров без отдельного запроса. Варианты: `docs/llm-options.md`.

## Архитектура

Backend — единственный владелец БД и правил обучения. Бот не обращается к БД напрямую.
Модули: `users`, `learning`, `vocabulary`, `placement`, `reminders`, `dialogs`, `recommendations`.
Структура модуля: models, schemas, service, router. Межмодульные изменения выполнять через
сервисы; границы транзакций должны быть явными. SDK LLM — только внутри адаптера.

Frontend обращается через `src/api/client.ts` и префикс `/api`; Vite проксирует его на
API. Общие маршруты сайта/бота используют `VocabularyUser`, обычные страницы — `CurrentUser`,
внутренние маршруты worker — `BotService`. ID владельца определяется сервером.

## Запуск и команды

Команды выполняются из корня проекта после запуска Docker Desktop. В PowerShell 5.1
вводить команды отдельными строками: `&&` не поддерживается этой версией оболочки.
Корневой `.env` содержит настройки БД, отдельные случайные `JWT_SECRET` и
`BOT_SERVICE_TOKEN`, `BOT_TOKEN`, имя того же бота без `@` в `BOT_USERNAME`.
Для работы без модели явно выбрать `LLM_PROVIDER=stub`.

```powershell
docker compose up -d db
docker compose stop api web bot
docker compose build api bot
docker compose run --rm api alembic upgrade head
docker compose run --rm api python -m app.seed
docker compose up -d db api web bot
```

Сайт: http://localhost:5173. API по стандартному compose: http://localhost:8000/docs.
При занятом внешнем порте допустимо `ports: ["8001:8000"]`, тогда API доступен на
http://localhost:8001/docs. Внутренние адреса `http://api:8000` остаются прежними.

```powershell
docker compose stop
docker compose up -d db api web bot
docker compose logs --since=5m --tail=80 api bot
```

API применяет миграции до старта. Seed обновляет материалы по естественным ключам,
не удаляя аккаунты/попытки и не сбрасывая SM-2. Не запускать два polling-процесса с
одним токеном. Демо `--demo` использует временные данные и не заменяет подключённый режим.
Локальные напоминания требуют включённых компьютера, Docker и интернета.

## Данные и миграции

- Схема меняется только через Alembic. Все модели регистрировать в `app/models.py`.
- Новые таблицы: FK, CHECK допустимых значений, естественные UNIQUE, осмысленный ondelete.
- Naming convention находится в `app/core/db.py`. Полные имена CHECK в миграциях
  передавать через `op.f(...)`, чтобы не получить двойной префикс.
- Общие ENUM не создавать повторно и не удалять при откате новых таблиц.
- Статистика и проценты вычисляются. Назначенные диагностические вопросы сохраняются
  как исторический снимок; изменение банка не переписывает старый результат.
- Сдача теста не меняет профиль. `/apply` меняет уровень и applied_at атомарно.
  Повторная сдача не перезаписывает сохранённые ответы.
- Массовое добавление слов: ON CONFLICT DO NOTHING, сохранение текущих дат и SM-2.
- Reminder settings и delivery — отдельные сущности; lease и claim token защищают
  конкурентную обработку. Повторы/ограничения описаны в `docs/reminders.md`.
- После изменения схемы обновить `docs/database.md`, выполнить DB-review по
  `.claude/agents/db-reviewer.md`. Проверить upgrade, alembic check и downgrade
  новых миграций на отдельной тестовой базе, не на пользовательской.

## Контент

| Файл | Назначение |
|---|---|
| `backend/content/course.json` | Теория, упражнения, слова уроков, типы ошибок |
| `backend/content/vocabulary_modules.json` | Тематические модули и иллюстрации |
| `backend/content/placement.json` | Версионированный банк диагностики |

Не переименовывать массово старые темы и тексты заданий: это естественные ключи seed.
Все допустимые ответы перечислять в `correct`; неоднозначные задания уточнять контекстом.
Для word_order первое правильное предложение задаёт доступные пользователю слова.
Правильные ответы выдаются только после попытки/сдачи.

Диагностика содержит по восемь вопросов A1/A2/B1. Она помогает выбрать стартовый материал,
не сертифицирует CEFR и не оценивает говорение, аудирование и уровни B2–C2.

Иллюстрации — собственные файлы в `frontend/public/images/vocabulary`.
Word.image_url допускает только `/images/vocabulary/<slug>.svg`. Не добавлять
в SVG скрипты, внешние загрузки или пользовательский HTML.

## Секреты и авторизация

- JWT в Authorization, пароли argon2; чужие слова, настройки и попытки недоступны.
- Telegram: одноразовый код на 10 минут, пароль сайта в боте не запрашивается.
- `.env`, Authorization и токены не читать при подготовке патчей, не печатать в логах,
  не включать в архивы и Git. Дампы БД также не коммитить.
- Проверки выполняются с искусственными значениями на отдельной БД.
  Настройки рабочего `.env` меняет владелец. Реальным пользователям тестовые сообщения не отправлять.

## Фронтенд

Маршруты: `/` курс; `/topics/:id` урок; `/vocabulary` модули/словарь;
`/review` повторение; `/profile` кабинет; `/placement?attempt=:id` диагностика;
`/talk` и `/talk/:id` интерфейс будущего собеседника.

Закрытые страницы — внутри RequireAuth. Для useApi передавать стабильный useCallback.
После применения уровня вызвать useAuth().refreshUser(). Показывать загрузку, ошибки,
подтверждение сохранения. Интерфейс русский; цвета через CSS-переменные проекта;
проверять тёмную тему и ширину 390 px. Название — константа APP_NAME.

## Проверки перед передачей

Порядок: `.claude/skills/verify/SKILL.md`. Изменения API/схемы/доставки проверять
тестами без реального Telegram и LLM. Изолированный backend-набор:

```powershell
docker compose --env-file .env.example -f compose.test.yml up --build --abort-on-container-exit --exit-code-from test-api
```

Другие проверки в своей локальной среде:

```powershell
docker compose run --rm bot python -m pytest -q
docker compose run --rm api alembic check
```

Frontend из frontend/: npm ci, npm run lint, npm run build, npm run test:e2e.
E2E требует запущенные API/сайт с seed и создаёт пользователей; использовать отдельную БД.
Если Docker недоступен, допустимы те же инструменты с изолированным PostgreSQL,
с честным указанием способа запуска. Отдельно сообщать пропущенные проверки.
Сборка и mocks сами по себе не доказывают реальную доставку Telegram.

## Git и обновления

Просматривать git diff/status перед commit; добавлять конкретные каталоги.
Не выполнять reset --hard, удаление Docker-томов или force push для установки обновления.
Пакет обновления проверяет SHA-256 до копирования и сохраняет резервную копию.
Windows-инструкция: `docs/windows-update.md`.
