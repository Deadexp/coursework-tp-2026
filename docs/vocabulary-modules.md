# Расширенный курс и тематические карточки

Курс в `backend/content/course.json` содержит 15 тем уровня A1–B1 и 90 упражнений:
по шесть заданий на тему. В теории есть утвердительные, отрицательные и
вопросительные формы, примеры и разбор типичных ошибок. Новые темы используют все
четыре существующих вида заданий: выбор варианта, пропуск, перевод и порядок слов.

## Темы курса

| Позиция | Тема                                      | Уровень |
| ------- | ----------------------------------------- | ------- |
| 1       | Articles: a / an / the                    | A1      |
| 2       | Present Simple                            | A1      |
| 3       | There is / There are                      | A1      |
| 4       | Prepositions of time: in / on / at        | A2      |
| 5       | Past Simple                               | A2      |
| 6       | To be and subject pronouns                | A1      |
| 7       | Possessives and have got                  | A1      |
| 8       | Present Continuous                        | A2      |
| 9       | Countable nouns: some / any / much / many | A2      |
| 10      | Comparatives and superlatives             | A2      |
| 11      | Future: will / going to                   | A2      |
| 12      | Modal verbs: can / must / should          | A2      |
| 13      | Present Perfect                           | B1      |
| 14      | Past Continuous                           | B1      |
| 15      | First and Second Conditionals             | B1      |

Названия первых пяти тем, формулировки их 30 заданий, коды ошибок и естественные
ключи исходных слов сохранены. Это важно для обновления существующей базы:
`seed` находит прежние записи и сохраняет их идентификаторы. Уже выполненные
задания остаются выполненными; история попыток и ошибок не пересоздаётся.

## Тематические наборы

Отдельный каталог `backend/content/vocabulary_modules.json` содержит шесть
модулей по шесть карточек. Они доступны независимо от грамматической темы.

| Slug      | Тема                    | Уровень | Слова                                             |
| --------- | ----------------------- | ------- | ------------------------------------------------- |
| `food`    | Еда                     | A1      | apple, banana, bread, cheese, carrot, egg         |
| `animals` | Животные                | A1      | cat, dog, rabbit, fish, bird, turtle              |
| `home`    | Дом                     | A1      | bed, chair, lamp, sofa, door, clock               |
| `travel`  | Путешествия и транспорт | A2      | bus, train, bicycle, airplane, suitcase, ticket   |
| `study`   | Учёба                   | A1      | book, pencil, notebook, ruler, backpack, scissors |
| `weather` | Погода                  | A2      | sun, cloud, rain, snow, umbrella, rainbow         |

У каждой карточки есть английское слово, перевод, транскрипция, пример и
собственная векторная иллюстрация. Все 36 SVG находятся в
`frontend/public/images/vocabulary/`; внешние картинки, эмодзи и встроенный
видимый текст не используются. Иллюстрации нарисованы для проекта из SVG-примитивов,
поэтому их можно редактировать вместе с исходным кодом.

## Хранение и миграция

Миграция `a26111200003` следует за `a26111200002` и добавляет:

- `words.image_url` — необязательный путь к локальной иллюстрации;
- `vocabulary_modules` — описание модуля, уникальные `slug` и `position`;
- `module_words` — связь модуля со словом и порядок карточек внутри модуля.

У `module_words` составной первичный ключ `(module_id, word_id)` и уникальная
пара `(module_id, position)`. Позиции положительные. Удаление каталожной связи
не удаляет слово, личный словарь или повторения. При удалении модуля его связи
удаляются каскадно. Количество карточек и число уже добавленных слов вычисляются
запросом, а не дублируются в таблицах.

`image_url` проходит одну и ту же проверку в Pydantic и PostgreSQL:
`^/images/vocabulary/[a-z0-9][a-z0-9-]*\.svg$`. Поле допускает `null` для обычных
слов без картинки. Адреса внешних сайтов, `data:` и переходы по `..` не принимаются.
В браузере путь относится к собственному frontend; приложение не скачивает
иллюстрации с внешнего сервиса.

Миграция использует уже существующий ENUM `cefr_level`. Откат удаляет только
новые таблицы каталога и поле картинки: общие слова, личный словарь и история
повторений сохраняются.

После применения миграций загрузка контента выполняется обычной командой:

```bash
docker compose run --rm api python -m app.seed
```

CLI загружает оба JSON-файла одной транзакцией. В тестах и скриптах можно
вызывать `seed(session, course, modules)`; прежний вызов `seed(session, course)`
поддерживается и не очищает иллюстрации, добавленные каталогом.

Повторный seed обновляет теорию, пояснения, варианты ответа и содержимое
существующих модулей. Модуль определяется по `slug`, слово — по сочетанию
`text + part_of_speech + translation`. Менять эти ключи для исправления описания
не нужно: изменение ключа означает новую запись. Порядок карточек внутри модуля
можно менять; существующие `Word`, `UserWord` и `WordReview` сохраняются.
Упражнения, исчезнувшие из файла курса, остаются в базе, поскольку на них могут
ссылаться попытки пользователей.

## API

Router находится в `app.modules.vocabulary.modules_router`. Все три операции
используют существующую зависимость `VocabularyUser`: авторизацию сайта либо
проверенный запрос связанного Telegram-аккаунта. Без авторизации возвращается
`401`, для неизвестного модуля — `404`.

| Метод и путь                        | Результат                                                              |
| ----------------------------------- | ---------------------------------------------------------------------- |
| `GET /vocabulary/modules`           | Модули по `position`, с числом карточек и личным прогрессом добавления |
| `GET /vocabulary/modules/{id}`      | Описание модуля и упорядоченные `words` с `in_vocabulary`              |
| `POST /vocabulary/modules/{id}/add` | Добавление недостающих слов; ответ `{"added": 6}`                      |

Сводка модуля содержит `id`, `slug`, `title`, `description`, `cefr_level`,
`position`, `word_count`, `in_vocabulary_count`, `cover_image_url`. Обложка —
первая доступная иллюстрация по порядку карточек. Детальная карточка использует
существующую схему слова с дополнительным необязательным `image_url`.

Добавление использует `INSERT … ON CONFLICT DO NOTHING` для `UserWord`.
У новых слов срабатывают существующие серверные значения SM-2: нулевой интервал,
ноль успешных повторений, коэффициент 2,5 и срок первого повторения сейчас.
Уже добавленные слова не обновляются: `added_at`, `next_review_at`, интервал,
коэффициент, число повторений и записи `WordReview` остаются прежними.
Повторный запрос для полностью добавленного модуля возвращает `{"added": 0}`.
Все личные счётчики вычисляются для текущего пользователя.

## Интерфейс

На странице «Мой словарь» появилась сетка тематических наборов. Внутри набора
можно листать карточки, выбирать слово, открывать перевод и пример, а затем
добавить все недостающие слова одной кнопкой. Состояние «В словаре» обновляется
после добавления и удаления слов без потери выбранного модуля и карточки.
Просмотр иллюстраций сам по себе не изменяет SM-2.

На странице «Повторить» показывается иллюстрация, если она есть у слова.
Оценивание и расписание остаются серверными. Ошибка сохранения повторения
показывается на текущей карточке, чтобы пользователь мог повторить запрос.
Сетка адаптируется к узкому экрану; карточки и управляющие кнопки доступны
с клавиатуры, а оформление использует существующие переменные темы.

## Проверка

`backend/tests/test_vocabulary_modules.py` проверяет каталог 6 × 6, наличие
безопасных локальных SVG, авторизацию, пользовательские счётчики, идемпотентное
добавление, сохранность SM-2 и истории, порядок карточек после повторного seed
и ограничение `image_url` в PostgreSQL.

`backend/tests/test_seed.py` проверяет полный курс 15 × 6, четыре вида заданий,
связи с типами ошибок, правильные ответы и повторную загрузку без дубликатов.
Отдельный сценарий расширяет базу с пяти тем до пятнадцати после верного и
неверного ответа: идентификаторы, попытки, ошибки и отображаемый прогресс должны
сохраниться. Проверки грамматических квизов также используют актуальный каталог
и по-прежнему проверяют отсутствие утечки ответов.

Команда для обычной тестовой среды проекта:

```bash
cd backend
uv run pytest -q tests/test_vocabulary_modules.py tests/test_seed.py tests/test_grammar.py
```

Проверки выполняются на отдельной тестовой базе PostgreSQL. LLM и внешние
сервисы для этих сценариев не требуются.

При проверке 12 ноября 2026 года на PostgreSQL 16.2 все 29 тестов из этих трёх
файлов прошли. Ruff для затронутого backend-кода и Oxlint с запретом предупреждений
для затронутых компонентов словаря прошли. Все 36 SVG отрендерены в контактный лист
и просмотрены для проверки различимости предметов и единого стиля.
