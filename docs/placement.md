# Диагностика стартового уровня A1–B1

Авторский учебный тест: 24 вопроса, по 8 на каждый уровень. В каждом блоке
4 грамматических задания, 2 лексических и 2 задания по коротким текстам.
Вопросы, варианты и объяснения находятся в `backend/content/placement.json`.
LLM, внешние API и дополнительные настройки для теста не используются.

## Что означает результат

За правильный вариант начисляется один балл. В версии `placement-a1-b1-v1`
порог блока — 6 из 8. Рекомендация консервативна: B1 требует прохождения всех
трёх блоков, A2 — A1 и A2; остальные результаты рекомендуют базовые материалы A1.
Если A1 не пройден, результат прямо сообщает, что владение A1 не подтверждено.
Высокий балл в старшем блоке не перекрывает пробелы в предыдущем.

Это ориентир для выбора материала, не сертификация CEFR. Говорение, аудирование
и развёрнутое письмо не проверяются; уровни выше B1 отсутствуют. Порог не прошёл
независимой психометрической валидации. Банк фиксированный, поэтому повторное
прохождение после просмотра ответов менее показательно. Ограничения возвращаются
в каждом завершённом результате.

## API

Все маршруты требуют обычный пользовательский Bearer JWT (`CurrentUser`).

| Метод и путь | Поведение |
| --- | --- |
| `POST /placement/attempts` | Создать тест, HTTP 201, вернуть вопросы без ключей ответов. |
| `GET /placement/attempts/{id}` | Получить собственный тест и сохранённый результат, если он сдан. |
| `POST /placement/attempts/{id}/submit` | Отправить ровно 24 ответа; проверка на сервере. |
| `GET /placement/history?limit=20` | Собственные попытки от новых к старым, максимум 50; вопросы опущены. |
| `POST /placement/attempts/{id}/apply` | По явному действию пользователя один раз применить рекомендованный уровень. |

Сдача: `{"answers":[{"question_id":"123","option_index":1}, ...]}`.
`question_id` — строковый идентификатор назначенного вопроса из ответа API,
уникальный для попытки; код из исходного JSON вместо него не принимается.
Индекс варианта начинается с нуля; принимаются только целые числа 0–3.
Все вопросы текущей попытки должны встречаться ровно один раз. Неполные,
дублированные, лишние и неизвестные вопросы дают HTTP 422. Идентичная повторная
сдача возвращает сохранённый результат, попытка изменить ответы после сдачи — 409.
Чужой или отсутствующий тест возвращает 404; незавершённый тест нельзя применить.

Все операции с одной попыткой используют одну форму ответа:

```text
AttemptRead {
  id, version, status: "in_progress" | "completed",
  started_at, submitted_at: datetime | null, applied_at: datetime | null,
  total: 24,
  questions: [{ id, position, level, skill, prompt, passage, options }],
  result: null | {
    recommended_level, correct, total,
    scores: [{ level, correct, total }], summary, limitations,
    answers: [{ question_id, option_index, correct_option_index, is_correct, explanation }]
  }
}
```

В истории `questions` всегда `[]`; полный тест доступен через GET по id.
До сдачи `result` равен `null`; объяснений и правильных индексов в заданиях нет.
Сдача сама **не меняет уровень профиля**. `/apply` атомарно обновляет общий
`users.cefr_level` и время применения. Повторное применение уже применённой
попытки не переписывает уровень, даже если позднее его изменили другим действием.
После применения клиент перечитывает `/users/me`.

## Хранение и миграция

Миграция `a26111200001` после `43519f5b65f9` создаёт четыре таблицы:

- `placement_attempts`: владелец, версия, порог, время начала/сдачи/применения.
- `placement_questions`: неизменяемый снимок назначенного вопроса, его уровня и навыка.
- `placement_options`: четыре варианта; частичный уникальный индекс допускает
  не больше одного правильного варианта на вопрос.
- `placement_answers`: единственный выбранный вариант на вопрос, внешний ключ
  гарантирует принадлежность варианта вопросу.

Баллы, процент и рекомендуемый уровень не дублируются в БД, а вычисляются из
ответов и снимка. Снимок и сохранённый порог позволяют читать историю после
редактирования исходного JSON. Версия также фиксирует правило последовательных
блоков; при изменении алгоритма требуется сохранить поддержку старой версии.
Вопросы и варианты каскадно удаляются вместе с попыткой/пользователем.
Сдача и применение блокируют строку попытки, чтобы параллельные запросы не
перезаписывали результат. Профиль меняется в той же транзакции через
`users.service.set_level(..., commit=False)`.

Для регистрации нужны модели `PlacementAttempt`, `PlacementQuestion`,
`PlacementOption`, `PlacementAnswer` в `app.models` и роутер из
`app.modules.placement.router` в `app.main`.
