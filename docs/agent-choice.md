# 1. Выбор ИИ-агента

## Что требовалось от агента

Проект — сайт, Telegram-бот, сервер с базой данных и интеграция с LLM — команда из трёх человек делает за один семестр. Отсюда требования к агенту:

1. **Многошаговые задачи целиком.** Не подсказывать по строчке, а написать модуль, запустить его, найти ошибки и исправить.
2. **Работа с терминалом.** Docker, миграции, тесты, git и GitHub — чтобы агент сам проверял результат на запущенной системе, а не только «писал код».
3. **Настраиваемый harness в репозитории.** Правила, разрешения и автоматические действия хранятся в git и одинаково работают у всех троих (это и пункт 4 курсовой).
4. **Независимость от редактора.** У каждой участницы свой редактор.

Сравнение составлено по документации инструментов на осень 2026 года; возможности агентов быстро меняются.

## Выбор: Claude Code

1. **Проверка на живой системе.** Агент сам поднимает Docker, применяет миграции, гоняет тесты, открывает сайт в браузере через Playwright и создаёт Pull Request через `gh`. Почти все ошибки из журнала ниже нашлись именно так, а не при чтении кода.
2. **Самый полный harness.** Инструкции, разрешения, хуки, скиллы и субагенты настраиваются файлами в репозитории — это прямо закрывает пункт 4 курсовой (см. `docs/harness.md`).
3. **Защита от опасных действий.** Каждая команда проходит через разрешения: например, агенту запрещено читать файл с паролями `.env`, и это сработало на практике (см. журнал).
4. **Любой редактор.** Агент работает в терминале, поэтому участницы не обязаны переходить на один редактор.

**Минусы, которые мы учитываем:**
- агент ошибается, причём уверенно — поэтому каждый результат проверяется тестами и на запущенной системе;
- он пишет много кода за раз — человеку нужно время, чтобы его просмотреть и понять;
- нужен интернет и подписка.

Реальные случаи, когда агент ошибся или результат пришлось исправлять. Колонка «Как нашли» показывает, какая проверка сработала.

|---|---|---|---|

| — | Агент попытался сам создать файл `.env` с секретами | Сработал запрет в настройках разрешений | Пользователь создал файл сам. Пример того, что harness защищает |
| #1 | ER-диаграмма на GitHub не была видна пользователю, отображался код | Пользователь сообщил | Агент отрисовал диаграмму в картинку через mermaid-cli и встроил её в документ |

Первая проверка этого теста была некорректной (откатила лишнее), агент заметил и повторил. Вывод: тест должен падать без исправления |

| #6 | Линтер нашёл 3 нарушения правил React | Линтер | Исправлены в коде, а не отключены |
| #6 | Два e2e-теста падали: тест читал карточку, пока сохранялся предыдущий ответ; неоднозначный поиск ссылки | Падение тестов, разбор причины | Ошибка была в тестах, а не в сайте — тесты исправлены |
| #7 | Хук автоформатирования Python ничего не делал: `ruff` не установлен на компьютере, только в контейнере | Проверка harness при написании этого документа | Хук запускает `ruff` в контейнере; проверено реальной правкой |
| #9 | Ошибка API при подключении ключа показывалась как общее «модель временно недоступна» — настоящая причина (ключ не привязан к workspace) терялась | Проверка подключения на настоящем ключе | Текст ошибки API теперь передаётся в сообщение и лог; добавлена настройка `ANTHROPIC_WORKSPACE_ID` |
| #9 | В запросе «слабые места ученика» подзапрос со счётчиками создавался трижды — три разных подзапроса вместо одного | Агент перечитал свой код до запуска | Подзапрос создаётся один раз. Затем тест подтвердил, что ошибки из упражнений и диалогов считаются вместе |
| #9 | На телефоне четвёртый пункт меню обрезался, а пузырь с одним сообщением растягивался на всю высоту чата | Скриншоты страниц, измерение ширины меню в браузере | Компактное меню на узком экране, выравнивание сообщений по верху |

**Выводы.** Автотесты и линтер нашли 4 проблемы. Остальные нашлись только при проверке вне тестов: на запущенной системе (цикл миграций, запросы к серверу, подключение к настоящему API), по скриншотам и при перечитывании кода; ошибку 500 тесты пропустили. Одну проблему заметил сам пользователь.

**Итог работы с агентом:** 9 Pull Request, 3 миграции БД, 61 автотест сервера и 13 тестов сайта в браузере.
