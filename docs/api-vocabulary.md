# Словарь и интервальное повторение — как пользоваться API

Памятка для сайта и Telegram-бота. Полное описание запросов и ответов — в Swagger: http://localhost:8000/docs (раздел **vocabulary**).

Сайт сохраняет авторизацию `Authorization: Bearer <token>`. Подключённый бот
использует те же адреса с `X-Service-Token` и `X-Telegram-ID`: это ID отправителя
личного сообщения, полученный ботом из Telegram, а не внутренний ID пользователя сайта.
Сервер проверяет ключ до обращения к данным и находит пользователя по существующей связи.
Пустой, стандартный или короткий (менее 32 символов) служебный ключ не работает.
Смешивание JWT и служебных заголовков отклоняется. Username и `user_id` из запроса
не меняют владельца словаря. Служебный ключ никогда не передаётся в браузер.

Привязка: `POST /telegram/link-code` с JWT возвращает одноразовую ссылку на 10 минут.
`POST /telegram/link` со служебным ключом принимает `code` и `telegram_id` отправителя.
Новая ссылка отменяет предыдущую; существующие связи не заменяются. Для сайта
есть `GET /telegram/status` с JWT, для приветствия бота — `GET /telegram/me`.

## Сценарий «повторение слов» (Quizlet-режим)

1. `GET /vocabulary/review?limit=10` — карточки, которые пора повторить сегодня. Каждая карточка — слово и 4 варианта перевода (`choices`), один из них правильный (`word.translation`). Пустой список — на сегодня всё повторено.
2. Показываем слово, пользователь отвечает.
3. `POST /vocabulary/{word_id}/reviews` с оценкой `quality` и `source` (`"web"` или `"bot"`). Сервер пересчитывает, когда показать слово снова (алгоритм SM-2), и сохраняет историю.

### Какую оценку отправлять

| Что произошло | `quality` |
|---|---|
| Выбрал неправильный вариант / нажал «Не помню» | `1` |
| Ответил правильно, но долго думал / нажал «С трудом» | `3` |
| Ответил правильно | `4` |
| Нажал «Легко» | `5` |

Ответ сервера: `interval_days` — через сколько дней слово появится снова, `next_review_at` — точное время.

## Остальные запросы

| Запрос | Зачем |
|---|---|
| `GET /vocabulary` | Весь личный словарь с состоянием повторения |
| `GET /vocabulary/page?page=0&page_size=8` | Страница словаря: `items`, `total`, `page`, `page_size`; размер 1–20, страницы с нуля |
| `GET /words?q=кош` | Поиск по общему словарю; `in_vocabulary` — уже добавлено или нет |
| `POST /vocabulary` `{"word_id": 5}` | Добавить слово из общего словаря |
| `POST /vocabulary` `{"text": "wolf", "translation": "волк"}` | Добавить своё слово |
| `POST /vocabulary/topics/{topic_id}` | Добавить все слова темы (ответ: сколько добавлено) |
| `DELETE /vocabulary/{word_id}` | Убрать слово из словаря |
| `GET /vocabulary/problem-words` | Слова, которые чаще всего не удавалось вспомнить за 30 дней — для «работы над ошибками» |

## Ошибки

`401` — нет или просрочен токен, `404` — слова нет (в словаре / в базе), `409` — слово уже в словаре, `422` — неверные данные (например, `quality` больше 5).

Для бота `403` означает непривязанный Telegram; `503` — не настроена служебная
авторизация. При недоступности API подключённый режим не использует демоданные.
Удаление затрагивает только личную запись и её историю; общий справочник и словари
других пользователей сохраняются. Строки слова и перевода обрезаются по краям;
пустые после обрезки строки отклоняются. Повторное добавление той же пары даёт `409`.

Результаты подключённого бота сервер принудительно отмечает `source="bot"`.
SM-2 и `next_review_at` общие для сайта и бота. Одновременные повторения одной
личной записи обрабатываются с блокировкой строки, без потери обновления.
Демонстрационные интервалы к этому контракту не относятся.


## Учебные сессии подключённого бота

Те же два способа авторизации действуют для /practice.
POST /practice/sessions с {"mode":"quiz"|"daily"} создаёт или возобновляет занятие.
GET /practice/sessions/{id} возвращает текущий шаг; ответы других пользователей недоступны.
POST /practice/sessions/{id}/reveal принимает position и открывает перевод карточки.
POST /practice/sessions/{id}/answers принимает position и ровно одно поле:
quality для карточки, option_index для выбора или answer для ввода слова.

Повтор идентичного ответа возвращает квитанцию без второго изменения SM-2.
Другой ответ на уже пройденный шаг и пропуск очереди отклоняются.
Правильное слово возвращается после ответа, а не в вопросе теста.
Дневная практика завершается один раз за дату UTC; незавершённая возобновляется.
Если личный словарь пуст, API возвращает 412. Если слов мало, занятие короче пяти шагов.
Обычные слова и переводы берутся из общего справочника; фиксированного демословаря нет.
Варианты ответа не дублируются, а при их отсутствии используется ввод по переводу.

GET /practice/progress — уровень, личные слова, даты, результаты и завершённые занятия.
GET/PATCH /practice/level — существующий уровень профиля (A1–C2).
Самооценки карточек исключены из количества правильных ответов.


## Грамматический мини-тест курса

`/grammar` использует те же способы авторизации, что `/practice`: JWT сайта либо
служебный ключ и фактический Telegram ID, разрешаемый через существующую привязку.
ID пользователя и источник из тела запроса не принимаются. Источник определяется
сервером: bot для Telegram, web для JWT. Бот не подключается к PostgreSQL напрямую.

| Маршрут | Назначение |
| --- | --- |
| `GET /grammar/topics` | Непустые темы курса и количество упражнений |
| `POST /grammar/quizzes` | `{ "topic_id": null }` — смешанный тест; число — выбранная тема |
| `POST /grammar/quizzes/answers` | `session_token`, `position` и ровно одно из `answer` / `option_index` |

Создание возвращает `session_token`, `topic_id`, `total` (1–5), `answered`, `correct`,
`completed`, `mistake_topics`, текущий `question`. В вопросе только `position`,
`topic`, `type`, `prompt`, `options` и `words`; правильные ответы и объяснение
возвращаются только после попытки. Типы: multiple_choice (индекс кнопки), fill_gap,
translate, word_order (текст). Проверка использует общий learning/checking.py.

Ответ возвращает `is_correct`, `correct_answers`, `explanation` и новое `state`.
Каждый принятый ответ записан в существующие attempts/mistakes. Сайт учитывает
его существующими запросами прогресса и слабых мест. Тест не меняет SM-2 словаря.

Для «Пройти ещё раз» передаётся необязательный `previous_token`: подбор отдаёт
предпочтение ещё не использованным заданиям. Внутри теста упражнения не повторяются;
смешанный тест по возможности выбирает разные темы. При ограниченном банке возможны
повторы между прохождениями.

Подписанный токен действует четыре часа и привязан к текущему пользователю.
Он передаётся только в JSON, не в URL и не в callback_data Telegram. Ключ подписи
отделён от ключа входа сайта. Токен не даёт вход в аккаунт. Повтор идентичного ответа
идемпотентен, в том числе при конкурирующих запросах; изменить принятый ответ нельзя.
Пропуск порядка — 409; чужой тест — 404; неверный/истёкший токен — 409;
неверный формат — 422; нет контента — 412; непривязанный Telegram — 403.
Отмена на клиенте не создаёт попытку. Принятые ответы сохраняются при перезапуске,
возобновление незаконченного теста в интерфейсе бота не реализовано.

`GET /practice/progress` дополнен `grammar_attempted`, `grammar_correct`:
все грамматические попытки общего аккаунта с сайта и из бота. Словарные
`attempted`/`correct` остаются отдельными счётчиками.
