# Обновление проекта на Windows из ZIP

Инструкция рассчитана на Windows PowerShell 5.1 и уже существующую папку проекта.
Установку программ, запуск контейнеров и отправку изменений выполняет пользователь.
Скрипты сами не запускают Docker и не выполняют commit или push.

## Применить файлы

Распакуйте ZIP обновления в **отдельную папку**, вне проекта. Рядом должны находиться
`Apply-Update.ps1`, `Prepare-Git.ps1`, `manifest.json` и каталог `files`.
Не копируйте каталог `files` вручную поверх проекта: скрипт сначала проверяет изменения.
Закройте редакторы, которые могут сохранять файлы проекта во время обновления.

В PowerShell замените оба пути своими. Выполняйте команды по очереди; при ошибке
остановитесь. Сначала остановите приложение, оставив базу `db` работающей:

```powershell
Set-Location "D:\coursework-tp-2026"
docker compose stop api web bot
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\coursework-update\Apply-Update.ps1" -ProjectPath "D:\coursework-tp-2026"
```

`ExecutionPolicy Bypass` относится только к этому запуску PowerShell; постоянные настройки
системы скрипт не меняет. Выполняйте скрипт только из ожидаемого вами архива обновления.

Скрипт проверяет наличие `docker-compose.yml`, `backend`, `frontend`, все входящие хеши,
пути и исходное состояние каждого заменяемого файла. При локальных отличиях он выводит
список конфликтов и прекращает работу **до копирования файлов проекта**. Сохранённые
локальные правки нужно согласовать/объединить; удалять их для обхода проверки не следует.
Отсутствующий исходный файл тоже считается локальным изменением. Если новый файл уже
существует с другим содержимым, он не перезаписывается.

Хеши вычисляются по UTF-8 тексту: начальный BOM удаляется, окончания CRLF приводятся к LF.
Обычная разница окончаний строк между Windows и Git не считается конфликтом.
Уже обновлённые файлы пропускаются, поэтому повторное применение того же архива безопасно
при отсутствии новых локальных изменений.

Перед заменой существующих файлов создаётся каталог **рядом с проектом**:
`coursework-backup-YYYYMMDD-HHMMSS`. В нём сохраняются только заменяемые файлы с исходными
относительными путями; секретные файлы туда не копируются. Если требуются только новые
файлы, каталог резервной копии не нужен. Сохраните резервную копию до проверки результата.
При ошибке диска/доступа во время копирования часть файлов может уже быть обновлена:
скрипт явно сообщит об этом, а резервные копии останутся на месте.

**Локальные `.env` и `docker-compose.yml` не читаются и не заменяются.** Поэтому ваша
настройка опубликованного API-порта `8001:8000` сохраняется. Скрипт также не трогает
`.git`, Docker-тома, базу и состояние контейнеров. Символические ссылки и junction в
затрагиваемых путях отвергаются. Проверка хешей обнаруживает повреждение/несовпадение,
но сама по себе не заменяет проверку происхождения ZIP.

## Обновить базу и запустить приложение

После успешного применения файлов выполните из папки проекта:

```powershell
docker compose build api bot
docker compose run --rm api alembic upgrade head
docker compose run --rm api python -m app.seed
docker compose up -d db api web bot
```

Переходите к следующей команде только после успешного завершения предыдущей. Миграции
добавят новые таблицы, seed — учебный контент. API и бот запускаются после этих шагов,
чтобы не обращаться к ещё не обновлённой базе. Существующая база и её данные сохраняются.
Откройте `http://localhost:5173`; опубликованный API остаётся на `http://localhost:8001`.

## Подготовить ветку Git

Для этого шага нужен установленный Git, доступ к GitHub и, если потребуется, ваша
авторизация. Укажите helper из той же распакованной папки обновления:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\coursework-update\Prepare-Git.ps1" -ProjectPath "D:\coursework-tp-2026"
```

Если `.git` **не было**, helper создаёт репозиторий непосредственно в выбранной папке,
добавляет `origin` `https://github.com/Deadexp/coursework-tp-2026.git`, получает `main`
и устанавливает индекс на `base_commit` из manifest с помощью `reset --mixed`.
Рабочие файлы при этом сохраняются: изменения обновления станут видны в Git.
Такой reset разрешён только для `.git`, созданного **этим же запуском** helper.

Если `.git` **уже существует**, helper проверяет точный корень репозитория, существующий
HEAD и `origin`, выполняет fetch и создаёт новую ветку от текущего HEAD. Reset, stash,
принудительное переключение и перезапись рабочих файлов не выполняются. Чужой `origin`
не заменяется. Родительский репозиторий вместо выбранного проекта не используется.
После ошибки прервите последовательность и разберите сообщение; повторный запуск
не даёт helper права сбрасывать уже существующий `.git`.

Имя ветки — `feature/coursework-completion`; если оно занято, добавляется уникальный
суффикс. **Используйте имя, которое helper напечатал**, если дальше работаете с веткой.
Личные настройки Git (`user.name`, `user.email`) helper не устанавливает.

## Проверить и отправить самостоятельно

Перейдите в проект и проверьте состав изменений:

```powershell
Set-Location "D:\coursework-tp-2026"
git status
git diff --stat
git add README.md CLAUDE.md .gitignore backend bot frontend docs scripts
git diff --cached --name-only
```

Убедитесь, что подготовленные изменения не содержат `.env`, ключей, локальной БД или
ненужных файлов. `git add` добавляет текущие изменения указанных каталогов, включая ваши
собственные; просмотрите их перед фиксацией. Затем при готовности:

```powershell
git commit -m "Complete coursework learning flows and Telegram reminders"
git push -u origin HEAD
```

Последняя команда отправляет текущую подготовленную ветку. GitHub может запросить вашу
авторизацию и права записи. Если Git попросит имя и email автора, настройте их осознанно
для своего аккаунта; helper не подставляет чужие данные. Никакой commit/push не происходит
до этих ваших команд. При ошибке команды не переходите автоматически к следующей.

Проверка помощников: статический просмотр и независимая ревизия; запуск в Windows
PowerShell 5.1 в рабочем окружении проверки был недоступен.
