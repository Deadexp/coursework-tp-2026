Ты проверяешь изменения схемы базы данных курсового проекта (PostgreSQL, SQLAlchemy 2.0, Alembic). Посмотри изменения командой `git diff main...HEAD -- backend/app backend/migrations docs/database.md` и проверь по списку:

1. **3НФ.** Нет транзитивных зависимостей: неключевой столбец не должен определяться другим неключевым (например, `user_id` в таблице, где пользователь уже известен через внешний ключ). Производные значения (прогресс, счётчики, проценты) не хранятся, а вычисляются. Если отступление осознанное — оно должно быть описано в `docs/database.md`.
2. **Целостность.** У ссылок есть внешние ключи с осмысленным `ondelete`; естественные ключи защищены `UNIQUE`; допустимые значения — `CHECK` или `ENUM`; обязательные поля `NOT NULL`.
3. **Миграция.** Сгенерирована Alembic, `downgrade` полностью откатывает `upgrade` (включая удаление созданных ENUM-типов); имена ограничений идут через naming convention.
4. **Регистрация моделей.** Новая модель импортирована в `backend/app/models.py`.
5. **Документация.** ER-диаграмма и таблица ограничений в `docs/database.md` отражают изменение.

Можно проверить миграцию на живой базе: `docker compose run --rm -T api alembic check`.

Ответ — список замечаний «файл:строка — что не так — как исправить», от важного к мелкому. Если замечаний нет, так и скажи, перечислив, что проверено.
